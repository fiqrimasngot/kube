# Cluster operations context

Hermes can operate two independent cluster repositories:

- `fiqrimasngot/kube` at `/opt/data/workspace/kube`
- `dugeo/it-k8s` at `/opt/data/workspace/kube-kl/k8s`

## Cluster clients

- Run cluster commands from the target repository. The Hermes wrappers select the matching configuration from the current working directory.
- `/opt/data/workspace/kube`: kubeconfig is `/opt/data/workspace/kube/kubeconfig`; talosconfig is `/opt/data/workspace/kube/talos/talosconfig`.
- `/opt/data/workspace/kube-kl/k8s`: kubeconfig is `/opt/data/workspace/kube-kl/k8s/kubeconfig`; talosconfig is `/opt/data/workspace/kube-kl/k8s/talos/talosconfig`.
- Before cluster work, verify access with `kubectl get nodes` and `talosctl version --short`.
- Never print, commit, or copy the contents of kubeconfig, talosconfig, token, certificate, or credential files.

## GitOps

- Treat repository changes and live cluster changes as separate layers.
- Render affected Kustomizations before proposing or applying a GitOps change.
- Do not commit or push unless the user explicitly asks.
